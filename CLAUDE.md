# bio.mapltours.com

The link-in-bio page for MAPL Tours Jamaica: one static Next.js page (output: export) plus one Netlify function.

- Data in `data/*.json` is exported from the main repo (`mapltours`, lib/airport-transfers.ts and lib/experiences.ts at HEAD). Re-export when fares change; never hand-edit prices.
- Every outbound link goes to mapltours.com with `utm_source=bio&utm_medium=bio` so bookings attribute to this page.
- `netlify/functions/lead.mts` sends the code email through Resend, once, with no follow-ups (dropped Sept 19 2026: a scheduled email cannot be recalled when the code is used). Needs `RESEND_API_KEY` on the Netlify site; with `HUBSPOT_SERVICE_KEY` (a service key, `pat-na1-…`) it also creates or updates the HubSpot contact (`netlify/lib/hubspot.mts`; run `node scripts/hubspot-setup.mts` once per portal for the custom properties).
- Trip tips (the newsletter opt-in, Sept 24 2026): the rules live in `lib/tips.mts` (box pre-ticked only for US visitors; a pre-ticked box counts as consent only in the US). `/api/geo` gives the page the country; `/tips` is the signed confirm page for the code email's yes and stop links and needs `TIPS_SECRET` (GET never records, only the button's POST does). Re-run `node scripts/hubspot-setup.mts` before deploying a change that adds properties.
  - The list is its own Resend segment, `TIPS_SEGMENT_ID` (create a "Trip tips" segment; unset, nobody is put on any list). **`BIO_AUDIENCE_ID` holds every code requester from before Sept 24 2026 as subscribed, and none of them asked for tips: never broadcast to it.** The code no longer reads it.
  - HubSpot `mapl_tips*` + `mapl_country` is the consent record and is written first: no `HUBSPOT_SERVICE_KEY`, or a portal without the properties, means nobody joins the list. A form never lifts a stop (Resend `unsubscribed`, or `mapl_tips_source` "code email stop" / "unsubscribe link"); only the signed yes link does, because it proves the mailbox.
  - Resend's global `unsubscribed` flag decides who is mailed. `netlify/functions/resend-webhook.mts` (`/api/resend-webhook`, needs `RESEND_WEBHOOK_SECRET`) copies Resend unsubscribes to HubSpot: add the endpoint in Resend with the `contact.updated` event. Until then HubSpot and the weekly report's total can include people who unsubscribed in Resend. A "reply stop" is handled by setting the contact unsubscribed in Resend (the webhook then updates HubSpot).
  - The mapltours.com popup's relay proves itself with `LEAD_RELAY_SECRET` (same value on both Netlify sites, sent as `x-mapl-relay`). Without it a request that says `channel: 'site'` is recorded as the bio page's own, with no country, so a pre-ticked box from it never counts.
- Trip tips welcome series (Resend automation "Trip tips welcome", Sept 24 2026):
  - Events: `tips.subscribed` (payload `{source}`) is sent ONLY when a yes reaches the `TIPS_SEGMENT_ID` segment for the first time, after the segment add succeeded (`startsSeries` in `netlify/lib/tips.mts`, read before the add): a yes HubSpot did not have before (`lead.mts`, and the `/tips` yes link, which may lift a stop), or a standing yes that is not on the segment yet, which is the retry after an earlier request wrote the HubSpot yes and then failed at the code email, the segment add or the resubscribe. Never for a repeat request from someone already on the list, a stop, a pre-tick that is not consent, without the segment, or when the membership lookup fails; a refused event is logged and never fails the request (a 429 is retried once). `booking.paid` (payload `{type: tour|transfer}`) is sent by mapltours.com's booking sync, and only for an address that is already a Resend contact.
  - Known gap: two requests for the same new yes that both read HubSpot before either records it, or where the second checks the tips segment before the first has added the address (a double tap on the no-JavaScript `/tips` button or form), can both send the event, and each run mails every tip. Nothing the bio uses has an atomic once-only write (HubSpot, Resend contacts, segments and events are all check-then-write); closing it needs one, for example Netlify Blobs `set(key, v, { onlyIfNew: true })` keyed on the address.
  - Graph: `tips.subscribed` → wait for `booking.paid` up to 2 days → tip 1 (the ride, `netlify/lib/tip-emails.mts`) → wait up to 12 days → tip 2 (three tours). A booking during a wait ends the run (the `event_received` branch goes nowhere); Resend skips the remaining sends for anyone who unsubscribes.
  - Setup: `node scripts/tips-automation.mts --dry` prints the plan and writes nothing; with `RESEND_API_KEY` and no flag it creates or updates the two events, the two templates (published, from/reply-to as the code email) and the automation, created **disabled**. Run it once before deploying so the events exist, and again after any change to `tip-emails.mts` or to the fares and tours in `data/transfers.json` / `data/tours.json` (the templates are snapshots: tip 1's fare table and tip 2's prices are read from those files when the script publishes, so Resend keeps the old numbers until it is re-run) (it republishes what differs, and any template with an unpublished draft, rewritten from the code first). Resend cannot change the steps of an enabled automation; the script reports that instead of forcing it.
  - **The automation stays disabled until `POSTAL_ADDRESS` in `netlify/lib/tip-emails.mts` is set** (the owner has not supplied it): `--enable` is refused while it is null, and without `TIPS_SEGMENT_ID` in the environment (the value on Netlify). Set the address, then run `RESEND_API_KEY=... TIPS_SEGMENT_ID=... HUBSPOT_SERVICE_KEY=... node scripts/tips-automation.mts --enable` (try it with `--dry` first): both templates are rewritten from the code and republished, then it is switched on. A disabled automation drops every `tips.subscribed`, so the first switch-on (an automation that has never had a run) reads the tips segment just before the switch and, once it is on, sends `tips.subscribed` (source `tips list`) to everyone on it who has not unsubscribed: the people who said yes while it was off. Test addresses and anyone HubSpot shows as having booked (`mapl_last_booking_at` or lifecycle stage customer) are left out; if HubSpot cannot be read, or the segment is longer than the script reads, it stays off. The output counts them and masks any address it could not start. Disabling it later and enabling it again starts nobody, so yeses during such a pause do not get the series. When it goes live, update "the first one comes in a couple of weeks" in `lib/tips.mts` and `netlify/lib/tips-page.mts` (tip 1 comes after 2 days).
  - Templates carry `{{{RESEND_UNSUBSCRIBE_URL}}}` in the HTML itself: automation sends add no unsubscribe link of their own. Nothing else in a template may contain `{{`.
- Copy rules: no em dashes, "MAPL Tours Jamaica" mixed case, drivers "pick you up", no invented reviews or statistics.
- Check every change at 390 and 1440 in a real browser and on the Slow 4G profile; the page exists to load instantly on a phone.
